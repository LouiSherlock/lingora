那第一版建议做成一个 **纯前端 + AI API 的英语练习网站**，暂时不引入数据库、Redis、用户系统和后台管理。

重点是先验证三个核心体验：

1. AI 能否生成质量不错的英语题目。
2. 用户能否流畅地完成答题、查看解析。
3. AI 能否根据用户答题情况，生成针对性的后续练习。

我建议使用 Next.js App Router，做成一个可以直接运行和体验的 MVP。

## **2. AI API 设计**

第一版只需要三个核心接口：

| API                  | 功能        |
| -------------------- | --------- |
| `POST /api/generate` | 生成练习题     |
| `POST /api/grade`    | 批改用户答案    |
| `POST /api/explain`  | 解释题目和回答追问 |

AI 题目生成建议使用结构化输出，利用 Zod 校验。

示例：

```
import { z } from "zod";

export const QuestionSchema = z.object({
  id: z.string(),
  type: z.enum([
    "single_choice",
    "fill_blank",
    "true_false",
  ]),
  level: z.enum([
    "A1", "A2", "B1",
    "B2", "C1", "C2",
  ]),
  knowledgePoints: z.array(z.string()),
  stem: z.string(),
  options: z.array(
    z.object({
      key: z.string(),
      text: z.string(),
    })
  ),
  answer: z.string(),
  explanation: z.string(),
});

export const PracticeSchema = z.object({
  title: z.string(),
  questions: z.array(QuestionSchema),
});
```

注意：这里是 MVP 示例 Schema。正式版还需要针对不同题型分别定义答案结构，尤其是填空、判断和多选，不能全部使用同一种答案格式。

## **3. AI 调用流程**

```
Browser
   |
   v
Next.js API Route
   |
   v
Validate Request (Zod)
   |
   v
Build System Prompt
   |
   v
AI Provider
   |
   v
Validate AI Response
   |
   v
Return Structured JSON
   |
   v
Render Questions
```

**安全方面有一个必须注意的地方：**

AI API Key 只能放在服务端环境变量中，不能使用 `NEXT_PUBLIC_` 前缀。

```
AI_API_KEY=your_api_key
AI_BASE_URL=https://your-provider.com/v1
AI_MODEL=your-model-name
```

前端不能直接请求模型服务，应该统一经过 Next.js Route Handler。还需要给生成、批改和追问接口增加请求大小限制、频率限制和费用控制。

# **五、无数据库情况下如何保存数据？**

第一版可以使用浏览器本地存储。

| 数据      | 保存方式                |
| ------- | ------------------- |
| 用户学习设置  | localStorage        |
| AI 模型配置 | localStorage（不保存密钥） |
| 练习历史    | IndexedDB           |
| 答题记录    | IndexedDB           |
| 错题本     | IndexedDB           |
| 学习统计    | 从本地记录计算             |
| 语法知识库   | TypeScript 静态数据     |

如果需要保存用户自己的 AI Key，建议只放在浏览器会话内存中，或者明确提示本地存储的安全风险；更推荐第一版统一使用服务端配置的 AI Key。

这样即使刷新页面，之前的练习记录也不会丢失。

这条完整链路跑通，就已经是一个可用的 MVP。

# **七、我建议额外确定一个技术决策**

你之前使用过 Next.js、Drizzle、Better Auth，也接触过多个 AI 模型。第一版最好把 AI Provider 单独抽象出来，避免以后切换模型时重构业务代码。

建议采用：

```
interface AIProvider {
  generatePractice(input: GenerateInput): Promise<Practice>;
  gradeAnswer(input: GradeInput): Promise<GradeResult>;
  explainQuestion(input: ExplainInput): Promise<ExplainResult>;
}
```

底层可以切换 OpenAI、Gemini、DeepSeek、Qwen 等，前端和练习系统不需要知道具体模型。

**确认的关键点：**

AI 模型如何接入？

- **A. OpenAI 兼容接口**：只需要配置 Base URL、API Key、Model，适合接入各种第三方模型。
- **B. 官方 SDK**：针对 OpenAI、Gemini, Opencode 等分别实现 Provider。
- **C. 两种都支持**：设置页面可以自由切换 Provider。
